- 정보 구조와 사용자 흐름
- Figma 흑백 와이어프레임
- Figma 고화질 UI 8개 화면
- 브라우저 기능형 PWA 프로토타입
- GitHub Pages 무료 공개 배포
- 실제 OpenStreetMap 지도와 장소 마커
- 현재 위치 표시와 지도 클릭 위치 선택
- 지도에서 선택한 위치를 장소 등록 화면으로 전달
- 장소 상세에서 외부 지도 열기와 위치 공유
- 사진 업로드 전 브라우저 자동 압축
- 입력 문자 수 제한과 사용자 입력 화면 출력 보호
- Expo/React Native 네이티브 소스
- Node.js 장소·컬렉션 MVP API
- 웹 프로토타입 Node API 연결 기반
- 회원가입·로그인 기본 구조
- 사용자별 장소·컬렉션 데이터 격리
- PostgreSQL 데이터 저장소와 JSON 데이터 이관
- 레거시 사용자 복구와 데이터 소유권 검증
- PostgreSQL 영구 세션 저장소
- Render 운영 배포와 프록시 origin 검증
- 서버 재시작 후 로그인 세션 유지 검증

## 현재 공개 환경별 저장 범위

### GitHub Pages 브라우저 데모

- LocalStorage 사용
- 로그인 없음
- 기기 간 동기화 없음
- Node.js API 없음
- 사진은 브라우저에 저장

### Render 서버 운영 환경

- PostgreSQL에 사용자, 장소, 컬렉션, 세션 저장
- 로그인과 사용자별 데이터 격리 적용
- 서버 재시작 후 로그인 세션 유지
- 이미지 스토리지가 아직 없어 사진은 현재 브라우저에만 저장
- GitHub Pages의 브라우저 fallback과 운영 서버 저장 방식은 서로 다름

## 통합 인증 전환 순서

1. 통합 인증 아키텍처와 사용자 마이그레이션 설계
2. 기존 `public.users.id`를 유지하는 nullable `auth_user_id` 매핑 migration
3. 서버 Supabase JWT 검증 계층과 기존 `yyj_session` 공존
4. 이메일 OTP 및 이메일 미제공 provider의 이메일 입력·OTP 보완 인증
5. Google 로그인
6. 카카오 로그인
7. Apple 로그인
8. 기존 이메일/비밀번호 사용자의 명시적 계정 연결
9. 기존 사용자의 비밀번호 재설정·계정 복구
10. 설정 화면의 로그인 수단 연결·해제
11. 충분한 전환 기간 후 자체 비밀번호·세션 종료 검토
12. 휴대폰 OTP와 네이버 로그인 검토

기존 사용자가 비밀번호를 잊어도 데이터 소유권을 잃지 않고 복구할 수 있어야 한다. 본인 확인이 끝나기 전에는 `auth_user_id`를 연결하지 않으며, 기존 자체 비밀번호·세션 종료보다 비밀번호 복구를 먼저 구현한다. 각 단계는 데이터 백업, 기존 owner ID와 로그인 회귀 테스트, 신규 인증 테스트, 실패 시 기존 인증으로 복귀할 롤백 지점을 확인한 뒤 배포한다.
